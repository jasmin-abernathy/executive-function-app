# Product principles

## 1. Reprise over performance

The app should make it easier to **return after interruption or absence**. It must not turn an interrupted day into a failure state.

No broken streaks, shame copy, leaderboards or punishment for missed days.

## 2. Reduce decisions before adding intelligence

A clever system that asks for extensive setup can be worse than a simple button. Prefer defaults, progressive disclosure and short paths.

## 3. Local-first core

Core planning, capture and focus features should not depend on a remote account. Network access must have an explicit purpose.

## 4. Complement existing tools

The product should not assume that it must replace calendars, notes, messaging, timers and every other tool. Integrations or hand-offs can be better than a forced all-in-one design.

## 5. Accessibility is core functionality

Readable typography, scalable text, reduced motion, screen-reader semantics, sufficient contrast and simple navigation are product requirements, not premium extras.

## 6. Automation stays understandable

When the app suggests, sorts or automates something, the user should be able to understand and override it. Avoid opaque productivity scores.

## 7. Optional game layer

A companion, room/house or progression layer may improve attachment for some users, but must remain optional and must never be the only way to access core functions.

## 8. No synthetic therapeutic relationship

A future companion can be warm, strange, quiet and playful. It is still a **game character**, not a therapist, diagnostician or simulated intimate relationship.

## 9. Privacy by architecture

Do not collect data simply because it might become useful later. Keep user-created content local unless an explicit feature requires otherwise.

## 10. Evidence before expansion

Advanced features belong after the core loop has been observed with real users. The backlog is not a promise.

## 11. Protect intention, not attention

The app should preserve and restore what the user intended to do, especially after an interruption or when returning to the app.

It should not compete for attention through infinite feeds, unnecessary badges, engagement loops, excessive notifications or guilt-based screen-time goals.

When useful context exists, reopening the app should surface the active task or next physical step before secondary content.
